在同一无 GT 泄露的 B1 协议下，验证"以 B1 为默认决策 + 两条受约束路由纠错支路"的 R 方法
能否在限制原成功样本回退与额外调用量的条件下提高 split0 SSR。设计来源：
`FreeGrasp_B1_选择性路由纠错_实验设计与执行交接_20261002.md`（design v1.1）。

## 阶段与门

1. **阶段0（零API）**：基线完整性验收（A 行/掩码对修复包 derived seal 全量哈希核对）、
   守卫复现（300/300）、支路可达性漏斗 → `baseline_parity.json`、`reachability.json`、
   `plan.json`、`frozen_protocol.json`。门：全部 PASS 才进入付费阶段。
2. **阶段1（小批付费）**：2 行支路 I + 1 行支路 O，端到端验证 payload、模型标识、
   调用数、最终 ID、掩码与评分链路。
3. **阶段2（其余付费）**：完成剩余触发行；禁止中途改规则或扫阈值。
4. **阶段3（封存评分）**：compose 组装 A/R/RI/RO → 独立评分 → `score.json` + `report.md`。

## 停止门（fail-closed）

- 传输异常、认证错误（HTTP 401/400）、状态不明请求：立即停止，不自动重发。
- 预算任一超限（调用数/费用/时长）：停止并封存。
- 源/配置/代码哈希漂移、非法 payload、身份或 usage 缺失：停止。
- HTTP 500：仅允许既有有限重试（≤3 次），计入账本。
- 结构性无掩码：每行一次预登记重试（镜像 resume8 worker），仍失败则按规则分类。

## 提交规则（预登记，design 3.4）

- 未触发行：逐字节复用冻结 A（哈希核验引用，0 新调用）。
- 新最终 ID == A 最终 ID：保留 A 的 mask_query/class_name/mask 整套输出；
  新推理单独存为核查轨迹。
- 新 ID 合法且不同：原子提交新 ID+新分割文本+新掩码。
- 新计划 ID 非法/缺失：保留 A，记录 candidate_invalid_keep_A。
- 计划合法但分割失败：按官方协议记该行失败，不因评分结果回退 A。
- 不把任何路线降为 direct；A=blocker_first 一律不干预。

## 判定标准（确认集开跑前冻结，design 7）

- 主比较：R−A 配对 SSR 差，scene 聚类 bootstrap 95%CI（10000 次，seed=20261002）。
- 提升声明需 CI 下界 >0；净增 <6 行（<2pp）称小幅改善；+2pp 为工程目标而非预测。
- RSR 非劣保护：单侧 95% 下界 > −1pp；样本不足记证据不足。
- 预算超限即整体目标未达成。
- split0 为已暴露开发数据：结论仅限探索性，不作为未见泛化证据。
